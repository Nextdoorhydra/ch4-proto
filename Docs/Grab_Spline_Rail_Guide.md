# 잡아서 움직이는 Spline 레일

## 클래스 선택

- `CMGrabRailActor`: 운반 물체, 손잡이, 슬라이더 등 공용 레일 장치. 활성화는 잡기 허용, 비활성화는 놓기/정지다.
- `CMGrabRailActor`에 문 메시를 지정하면 수동 미닫이문으로도 사용할 수 있다. 별도 문 전용 클래스는 없다.
- `CMRailMovementComponent`를 사용하고 기존 팔의 `CMArmHoldTarget` 계약을 전달하므로 팔/레버 코드를 수정하지 않는다.

## BP 만들기

1. 해당 C++ 클래스를 부모로 하는 BP를 만든다.
2. `MovingMesh`에 메시를 지정한다. 메시 자체 충돌은 끈 채로 둔다.
3. `RailBody`의 Box Extent를 메시 전체에 맞춘다. 이것이 이동 충돌 검사 형상이다. 이동하는 자식 메시의 별도 충돌은 지원하지 않는다.
4. `GrabHandle`을 손잡이에 배치한다. Sphere는 잡기 탐색용이며 팔이 그 범위 안에 있어야 한다.
5. `Rail`의 Spline 점을 편집한다. 직선은 Linear, 곡선은 Curve 계열 점을 사용한다. Closed Loop는 지원하지 않는다.
6. Spline 위치는 **움직이는 충돌 박스 중심**의 경로다. 문 바닥이 바닥에 닿도록 레일 높이를 지정한다. 메시 피벗 보정은 메시 자식의 상대 위치로 한다.
7. `RailMovement.InitialProgress`로 시작 위치(0~1)를 정한다. 문으로 쓸 경우 첫 점을 닫힘, 마지막 점을 열림 위치로 배치하고 1로 설정하면 열린 상태에서 시작한다.
8. `Start Active`는 잡기 허용 여부다. 열림 정도와는 관계없으므로 수동 조작하려면 true로 둔다.

레일/액터 루트는 고정하고 충돌 박스와 그 자식만 움직인다. 잡힌 손 IK는 GrabHandle을 따라간다. 문틀을 추가한다면 고정 루트 아래에 붙이고 레일 이동 여유를 확보한다. 동일 액터의 문틀도 충돌 검사에서 제외하지 않는다.

## 조절 값

- `Follow Rail Rotation=false`: 문 방향을 유지한다. true면 곡선 방향을 따라 회전한다.
- `Rotation Offset`: 고정 방향 또는 곡선 회전 프레임 기준의 추가 회전.
- `Pull Sensitivity`: 팔 이동량 대비 레일 이동량 배율.
- `Max Move Speed`: 프레임당 이동 제한 및 외부 명령 이동 속도. Spline 거리 단위 기준이므로 액터 Scale은 1을 권장한다.
- `Collision Step Distance`: 곡선을 나눠 검사하는 최대 거리. 기본 2cm. 빠른 이동/급곡선은 작게 설정한다.
- `Release Distance`: 손잡이와 팔이 너무 멀어지면 자동 해제한다.

손을 놓거나 팔이 무효화되면 중간 위치를 유지한다. 막힌 동안의 이동량은 저장하지 않으므로 장애물이 사라져도 누적된 거리만큼 튀지 않는다. 동시에 한 팔만 잡는다. 경로 자체는 런타임에 편집/복제하지 않는 고정 경로다.

## 스테이지 명령과 선택적 자동 이동

- Activate: 잡기 허용.
- Deactivate: 잡기 해제 및 이동 중단. 현재 위치는 유지한다.
- Reset: 초기 위치로 즉시 복원. **Reset만 충돌을 무시**하므로 플레이어와 겹치지 않는 리셋 타이밍에 호출한다.
- 자동 이동이 필요하면 서버에서 `RailMovement.MoveToProgress(0~1)`를 명시적으로 호출한다.
- 실제 끝점 도착 시 `RailMovement.OnEndpointReached`를 알린다. 기존 문 시스템의 `OnDoorTransitionFinished`나 룸 진행과 자동으로 연결되지는 않는다.
- `RailMovement.OnMovementBlocked`에서 막힘 소리를 연결할 수 있다. 자동 이동은 막히면 중단하므로 필요한 경우 명령을 다시 요청한다.

## 충돌/네트워크 범위

서버가 열린 Spline 위 진행률을 계산하고 컴포넌트의 복제된 Progress로 클라이언트 위치를 갱신한다. 클라이언트는 충돌을 다시 판단하지 않는다. 소유 액터의 Replicates를 끄면 안 된다. 훅/단발 당김은 이번 구현 대상이 아니며 일반 팔 홀드를 사용한다.

곡선은 작은 구간의 박스 Sweep으로 검사한다. 회전하는 구간은 회전 이동을 감싸는 보수적인 팽창 박스로 검사하므로 좁은 구간에서 조금 일찍 멈출 수 있다. 정확한 강체 물리 슬라이더/연속 회전 CCD가 아니다. 문을 물리 시뮬레이션 대상으로 바꾸지 않는다. 충돌 박스가 바닥/문틀/플레이어와 처음부터 겹치지 않게 배치한다.

## 검증

자동화 테스트: `Chimera.Rail.MovementRegression`.
PIE에서 추가 확인: 두 클라이언트에서 같은 위치, 중도 참가, 손 놓기/팔 분리, 끝점, 벽/몸통 차폐, 곡선 양방향 이동, 끝점 도착 이벤트, Reset. C++ 테스트만으로 실제 팔 입력/네트워크 시각 품질 검증을 대체하지 않는다.
